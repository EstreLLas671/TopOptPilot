# 4.1.2 实际计划输出

本作品中的"计划"，不是一份预先写好的静态任务清单，而是研究推进过程中由系统逐步生成、每一条都能回溯到真实实验证据的动态任务。下面以一次真实运行的三维悬臂梁研究（研究编号 R-001，运行于 2026 年 9 月 3 日的 TopOptPilot 2.0.9）为例，展示系统真实生成的一段计划，说明每项任务包含哪些内容，以及这些计划如何被交给实验、仿真或人工环节去执行。本机研究数据库目前已积累 263 份真实计划提案和 141 个真实实验记录，本节内容全部摘录自其中的完整链路。（早期记录中的层级编号 F0–F3，在现行版本中已统一规范化为 Step1–Step4，下文一律采用新表述。）

## 一、一段真实生成的计划

这项研究的第六轮，按计划在 Step3（Python 三维粗网格）完成了一次真实求解，即实验 E122。确定性评估器依据真实求解结果作出判定：该实验部分成功——结构柔度降到 0.1836，结构保持连通（连通分量为 1），但灰度单元比例为 13.4%，仍明显高于研究立项时设定的 5% 上限。评估器据此把下一轮的科学方向确定为"消除灰度"。

随后用户在流程弹窗中确认"推进到下一层级"，工作层级切换为 Step4。系统随即着手生成新计划；生成过程中在线大模型恰好不可用，系统的确定性规则策略自动接管，仍然产出了一份完全合规的计划——这也说明计划的生成不依赖在线模型的可用性。这份计划在系统中的真实记录如下（编号 P-C1DA8D1CD0，节选）：

```json
{
  "id": "P-C1DA8D1CD0",
  "intent": "REDUCE_GRAYNESS",
  "purpose": "Reduce grayness with one bounded projection step",
  "fidelity": "STEP4",
  "backend": "matlab",
  "parameters": {
    "volfrac": 0.4, "penal": 3.0, "rmin": 2.0,
    "beta": 32.0, "beta_max": 2.0,
    "projection": "heaviside_projection",
    "controller": "periodic_controller",
    "move": 0.1, "max_iter": 80, "min_iter": 10,
    "filter_strategy": "fixed"
  },
  "controlled_factors": ["beta"],
  "estimated_cost": 30.0,
  "risk": "HIGH",
  "safety_status": "PENDING_HUMAN_APPROVAL",
  "approval_required": 1,
  "source_experiment": "E122",
  "evidence_ids": ["E117", "E118", "E119", "E120", "E121", "E122"],
  "policy_version": "v6-intent-compiler-1",
  "status": "PREVIEW"
}
```

用自然语言来读，这份计划说的是：第六轮实验的投影强度已经升到编译器允许的上限 32，无法继续上调，因此本轮任务把这套参数组合——0.4 的体积分数上限、惩罚因子 3、滤波半径 2、Heaviside 投影配合周期性控制器与 0.1 的步长移动限制——原样提升到 Step4，交由本机 MATLAB 在真实精细网格上重新求解，检验更高保真度下这套配置能否把灰度率压回约束以内。计划同时声明：执行代价预估为 30 个成本单位，风险评级为高，必须等待人工审批，未获批前只能停留在"预览"状态。

作为对照，同一项研究首轮生成的计划则"轻"得多：科学意图是"探索参数"，在本机 Python 二维粗网格上执行，预估成本 1、风险评级低、安全校验直接通过、免于人工审批，生成后即刻提交为真实实验。两相对比可以看出，计划的规模与把关强度并非人为指定，而是随执行层级与风险自动升级——越接近真实仿真、消耗越大，计划需要的证据与人工把关就越严格。

## 二、每项任务包含哪些内容

每一项计划任务，实质上是对六个问题的完整回答。

**其一，为什么做。**每项任务都带有明确的科学意图和一句目的陈述。科学意图只能从预置的白名单中选取——建立基线、探索参数、消除灰度、恢复连通性、对比竞争性解释、升级保真度——从源头上杜绝了智能体提出含糊或越界的实验。上例的意图正是承接第六轮诊断结论的"消除灰度"。

**其二，在哪里做。**执行层级决定任务由哪个求解器、什么精度的网格承担：Step1 与 Step2 由本机 Python 二维求解器完成粗网格筛选与自适应验证，Step3 交给 Python 三维求解器，Step4 则由 MATLAB 在真实精细网格上执行。层级与后端的映射关系是固定的，计划只能选择层级，不能另行指定后端，更不能触碰已经锁定的几何、载荷、材料、网格与迭代上限等权威配置——这些内容在研究立项时即写入契约，全程不可更改。

**其三，允许改什么。**这是计划科学性的核心。任务参数中真正可调的只有六个白名单因子：体积分数、投影强度及其上限、投影方式、迭代控制器和步长移动限制；同时每项任务必须声明"受控变量"，即本轮唯一改变的因素。上例声明的受控变量是投影强度，其余条件与来源实验完全一致，保证结果差异只能归因于这一个因素。这从机制上落实了单因子受控比较的实验设计原则，也杜绝了把多因素混杂的差异当成结论的风险。

**其四，代价与风险多大。**每项任务自带预估成本与风险评级，由网格规模与后端自动评定：粗网格筛选的成本为 1、低风险，MATLAB 精细求解的成本为 30、高风险。成本与风险并非只是展示——高风险等级正是触发更严格审批条件的依据之一。

**其五，依据什么。**每项任务都记录着自己的证据链：它由哪个实验的结果驱动（上例的来源实验是 E122），参考了哪些真实证据（上例引用了此前六个实验的完整记录）。任何一份计划都能回答"你凭什么提出这个实验"，这是"计划不得脱离真实证据"这一原则的制度化。

**其六，由谁把关。**每项任务携带安全校验结论和是否需要人工审批的标记。凡升级到 Step4 的计划一律标记为"待人工审批"，未经批准不会启动；同时每份计划都登记生成它的策略编译器版本与决策来源，保证事后可审计、可复现。

## 三、计划如何交给实验、仿真与人工环节执行

计划生成之后，去向由它的层级与安全状态决定，共有三条路径。

**第一条路径：自动交给真实实验（Step1–Step2）。**低层级计划通过安全与策略校验后，自动创建实验并进入后台队列，由内置 Python 有限元求解器真实求解，逐轮产出柔度、体积分数、灰度率、连通分量等真实指标与密度数据，再由确定性评估器整理为结构化证据。值得注意的是，求解失败的任务不会被隐藏，也不会被"反复重试直到成功为止"：本机数据库现有 27 个真实完成与 113 个真实失败的实验记录，失败实验原样保留，作为有效的科学证据参与后续诊断。

**第二条路径：交给仿真求解（Step3–Step4）。**Step3 计划交给 Python 三维求解器执行，例如上文提到的 E121、E122 两次 24×8×6 网格的三维求解；Step4 计划则通过 MATLAB 适配器驱动本机 MATLAB 执行真实仿真，逐轮发布迭代收敛图、密度分布与指标制品，所有制品均带哈希校验，防止结果被替换或篡改。

**第三条路径：交给人工环节。**人工把关固定嵌在三个位置。其一，Step4 计划启动前必须经过审批：系统弹出决策窗口，完整展示参数、风险与证据链，用户批准后 MATLAB 任务才被放行，拒绝则计划作废。其二，Step4 升级计划生成的同时，系统自动派发一个独立评审子任务，由独立于规划角色的评审者复核证据是否充分、比较是否受控、预算是否值得、安全是否达标，并被明确要求"只审、不得自行提交"。其三，也是最有约束力的一道关：每个 Step 完成一个实验后，整个流程强制暂停，系统提示用户"本层级已完成，请确认进入下一流程，或在本层级再进行一轮"，只有用户明确选择之后，系统才会生成并执行下一阶段的计划——R-001 中就留有真实决策记录：第三层级完成后用户确认推进，系统才把工作层级切换到第四层级。系统绝不会替用户消耗下一步计算。

**由此形成计划闭环。**每轮执行结束后，系统基于真实结果完成比较、优选与问题诊断，生成下一轮计划建议，并落盘一份轮次报告（R-001 已存档六份）。本节摘录的 Step4 计划，正是第六轮诊断出"灰度率超标"后自动生成的下一步任务：计划从真实证据中诞生，交给真实求解器执行，关键节点由人工决策，全过程留痕、可审计。

在无界面场景下，这套计划合同同样向外部智能体开放：命令行入口可以查询计划，但任何真实计算都必须由用户显式确认后才会启动，与桌面端遵循同一套策略约束。

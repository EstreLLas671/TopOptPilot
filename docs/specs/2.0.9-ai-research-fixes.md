# TopOptPilot 2.0.9 AI Research Fixes

This document records the user-approved acceptance contract for the 2.0.9
release. It is the specification source for the post-implementation review.

## Authoritative configuration

- New research identifiers are neutral `R-xxx` values. Existing identifiers
  remain readable and never imply a load case.
- An approved Optimization Configuration is authoritative for geometry, load
  case, material, mesh and visible optimization parameters. Engineering
  imports copy that configuration without guessing from names or identifiers.
- Autonomous proposals may vary one controlled factor at a time. The only
  mutable factors are `volfrac`, `beta`, `beta_max`, `projection`, `controller`
  and `move`; all other visible configuration is locked.

## Fidelity workflow

- A 3D research runs F0 Python 2D at 50% XY, F1 Python adaptive coarse 2D at
  50%, 67% or 75% XY, F2 Python 3D at 50% XYZ, and F3 MATLAB 3D at the exact
  configured grid.
- Every autonomous research runs the complete F0-F3 sequence. Repeating a
  stage never advances it. Rejecting an F3 result remains at F3 for another
  MATLAB 3D round. Research finishes only after a successful,
  configuration-matching F3 MATLAB result is explicitly approved.
- F3 uses F2 density as a warm start but performs a full MATLAB optimization;
  fixed-density verification is not a completed F3 workflow.

## Reports and release

- Every research report contains the summary and Chapters 1-4 only.
- Product, API, report, audit and installer versions are 2.0.9.
- Existing desktop layout and styling remain unchanged except for required
  fidelity labels and decision wording.

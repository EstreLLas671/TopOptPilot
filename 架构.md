> **V5.0 覆盖说明**：现行主链为 Streamlit → ResearchService → 官方 Pi RPC →
> 11 Tool Gateway → Safety Policy → Async Python/MATLAB FEM → Evaluator → L0–L3 Memory。

### 核心设计原则

1. **大模型不代替有限元求解器** — PiAgent/DeepSeek 负责研究推理与工具编排，CUDA MEX 负责确定性数值计算
2. **论文方法工程化** — 论文不是被总结成文字，而是转化为带证据与验证状态的可执行 MATLAB 插件
3. **客观裁决** — 评价器用残差、柔度、灰度比例、连通性等指标裁决方案，Agent 不能自评
4. **全链路可复现** — 论文页码、配置版本、代码提交、随机种子、原始结果全部绑定

## 2. AI Scientist 状态机

### 状态转换图（含缺失状态标注）

```
INIT ──→ INPUT_VALIDATION ──→ LITERATURE_MINING ──→ HYPOTHESIS_GENERATION
                              │                      │
                              └──→ FAILED            ├──→ HYPOTHESIS_REVIEW
                                                     │    │
                                                     │    ├──→ EXPERIMENT_DESIGN
                                                     │    │    │
                                                     │    │    ├──→ HYPOTHESIS_GENERATION（回退）
                                                     │    │    └──→ [假设精炼] 🔴缺失
                                                     │    │
                                                     │    └──→ HYPOTHESIS_GENERATION（回退）
                                                     │
                                                     └──→ LITERATURE_MINING（回到文献挖掘）

EXPERIMENT_DESIGN ──→ EXPERIMENT_EXECUTION ──→ RESULT_AUDIT
                     │                         │
                     ├──→ [求解器诊断] 🔴缺失   ├──→ CONCLUSION（满足终止条件）
                     └──→ HYPOTHESIS_GENERATION ├──→ EXPERIMENT_DESIGN（修正后重做实验）
                                                 ├──→ LITERATURE_MINING（文献不足）
                                                 ├──→ HYPOTHESIS_GENERATION（假设需修正）
                                                 └──→ [区分性实验] 🔴缺失

[假设精炼] ──→ EXPERIMENT_DESIGN（保持假设方向，调整参数/条件）
[求解器诊断] ──→ EXPERIMENT_DESIGN（修复后重做实验）
               └──→ FAILED（不可修复）
[区分性实验] ──→ RESULT_AUDIT（专门设计区分假设的对比实验）

CONCLUSION ──→ [终止]
FAILED ──→ [终止]
```

**🔴 三个缺失的关键状态：**

| 缺失状态                               | 触发条件                           | 应做的事                                              |
| -------------------------------------- | ---------------------------------- | ----------------------------------------------------- |
| 假设精炼 (Hypothesis Refinement)       | 假设被部分否定，但方向仍有价值     | 保留原始假设的合理部分，调整参数/权重/条件，生成 H1.1 |
| 求解器诊断 (Solver Diagnosis)          | GPU/CPU 偏差过大 or 残差持续不达标 | 停止科学结论，进入求解器诊断；修复后重做实验          |
| 区分性实验 (Discriminating Experiment) | 两组假设的实验结果无法区分         | 设计一个在两个假设预测分歧最大的点进行测试的实验      |

### 终止条件

1. **成功达标**：达到成功门槛，并通过至少一个跨网格或跨载荷验证
2. **无信息增益**：连续 N 轮实验无法区分候选假设
3. **预算耗尽**：计算预算或时间预算用尽
4. **不可信证据链**：发现输入、求解器或插件证据链不可信，转人工
5. **假设被否定**：明确输出否定证据，并提供下一步研究建议

## 3. Paper-to-Plugin 流水线

### 流程

```
论文PDF → [1] 方法拆解 → [2] 证据定位 → [3] 重复插件检索
        → [4] 插件规格生成 → [5] 实验性代码生成
        → [6] 梯度检查 → [7] 基准复现 → [8] 状态登记
```

### 两个知识库

```
论文证据库（Agent 可检索）                可信插件库（仅用于正式实验）
┌─────────────────────┐               ┌──────────────────────┐
│ PDF + DOI + 方法卡片  │               │ 通过测试的MATLAB插件   │
│ 原文页码 + 公式 + 参数 │               │ 接口版本 + 验证记录    │
│ 适用条件 + 局限      │               │ CPU/GPU一致性已通过    │
│ 状态：非结构化        │               │ 状态：Verified         │
└─────────────────────┘               └──────────────────────┘
        │                                        │
        └── 检索、比较、提出候选 ────→ 经 Paper-to-Plugin ──→┘
```

### 插件生命周期

```
Candidate (仅论文提炼)
    │ 规格说明完整
    ▼
Experimental (已有代码原型)
    │ 单元测试通过 · 梯度检查通过 · MBB复现通过
    │ 三维小案例通过 · CPU/GPU一致性 · 人工批准
    ▼
Verified (可进入正式实验)
    │ 发现缺陷或被替代
    ▼
Deprecated (禁止用于新结论)
    │ 缺陷已修复 + 重新验证
    ▼
Verified (恢复)
```

### 合法组合规则（部分）

| 组合                         | 状态          | 原因                     |
| ---------------------------- | ------------- | ------------------------ |
| OC + 体积分数 + PDE 滤波     | ✅ 允许       | 单约束最小柔度基线       |
| OC + 多个局部应力约束        | ❌ 禁止       | 当前 OC 接口不支持多约束 |
| MMA + 位移约束 + 正确灵敏度  | ⚠️ 条件允许 | 必须先通过梯度检查       |
| Heaviside + 无链式导数       | ❌ 禁止       | 返回梯度不完整           |
| Experimental 插件 + 正式结论 | ❌ 禁止       | 尚未完成基准验证         |

## 4. CUDA MEX 求解器接口

### 标准生命周期

```
handle = solver.create(model, boundary, options)
    │ 只执行一次：网格/节点映射/多重网格层级常驻显存
    ▼
[result, state] = solver.analyze(handle, density, material, initialState)
    │ 每轮仅传入密度与材料
    │ 在 CUDA 内完成: Matrix-free K·u → PCG → 单元柔度 → 灵敏度
    │ 完整位移场仅在指定轮次返回，避免不必要数据搬运
    ▼  (重复多轮)
solver.destroy(handle)
    │ 释放显存
```

### 数值验收门槛

| 检查项           | 建议门槛                           | 说明                            |
| ---------------- | ---------------------------------- | ------------------------------- |
| 相对残差         | 按问题规模设定（如 10⁻³~10⁻⁶） | 不得只看 converged 布尔值       |
| CPU/GPU 柔度误差 | 中小基准达到预设容差               | 门槛按 FP64/FP32 分别制定       |
| 位移场误差       | 相对 L2 与最大节点误差             | 固定自由度应完全一致            |
| 灵敏度误差       | 随机单元有限差分抽检               | 发现链式导数缺失                |
| 拓扑一致性       | 阈值后二值相似度与关键构件一致     | 不要求浮点逐位相等              |
| 显存稳定性       | 连续多轮无增长和泄漏               | create/destroy 与异常路径均测试 |

## 5. 实验矩阵设计

### 核心实验组（参照方案 §9.4）

| 实验组   | 插件组合                              | 回答的问题               | 假设 |
| -------- | ------------------------------------- | ------------------------ | ---- |
| B0       | OC + PDE滤波 + 无投影 + 固定p         | 无延续基线表现如何       | H0   |
| B1       | OC + PDE + 固定轮次 β 延续           | 人工固定调度能改善多少   | H3   |
| A1       | OC + PDE + 灰度反馈 β                | 单一灰度指标是否足够     | H2   |
| A2       | OC + PDE + 收敛反馈 β/p              | 柔度稳定性是否能判断时机 | H2v2 |
| Ours     | 灰度 + 柔度 + 连通 + 求解难度联合反馈 | 核心假设是否成立         | H1   |
| Ablation | 逐项移除四类反馈                      | 每个信息源的实际贡献     | —   |

### 三级方法选择机制

```
[第一级] 硬约束过滤
  根据目标、约束数量、维度、所需梯度和插件状态排除非法组合

[第二级] 证据排序
  综合论文支持、相似历史案例、预期收益、失败风险与计算预算评分

[第三级] 小规模试验
  前2~3个方案先在粗网格运行，通过残差和可行性门槛后才进入正式网格
```

## 6. 结果判定与迭代动作

### 诊断规则（§7.3 + 优先级补全）

| 优先级 | 观察结果           | 诊断                   | 下一步动作                                              |
| ------ | ------------------ | ---------------------- | ------------------------------------------------------- |
| 🥇     | 出现 NaN/Inf       | 求解器数值异常         | 立即停止该轮，回滚到最后稳定 checkpoint，标记求解器诊断 |
| 🥇     | 出现多个连通分量   | 结构断连               | 回滚参数、扩大滤波半径或增加连通保护                    |
| 🥇     | GPU/CPU 偏差过大   | 精度或内核错误         | 停止科学结论，进入求解器诊断                            |
| 🥈     | 残差未达标         | 物理解不可信           | 不更新密度；收紧/更换预条件或回滚                       |
| 🥈     | 灰度下降但柔度突增 | 投影过快或陷入局部最优 | 降低 β、延迟投影、补对照                               |
| 🥈     | 不同网格结论相反   | 参数不具尺度一致性     | 用归一化半径与反馈重新设计                              |
| 🥉     | 全部指标达标       | 候选方案获得支持       | 进入细网格与独立复核                                    |

> 当多条规则同时触发时，优先级决定处置顺序：NaN/断连 > 求解器/残差 > 灰度/网格 > 全部达标。

### 假设模糊度检测（建议新增）

```python
class HypothesisQualityChecker:
    @staticmethod
    def check_falsifiability(hypothesis) -> dict:
        issues = []
        if not hypothesis.failure_conditions:
            issues.append("缺少失败条件 -> 假设不可证伪")
        if "might" in hypothesis.statement.lower() or "\u53ef\u80fd" in hypothesis.statement:
            issues.append("假设表述含不确定词汇")
        if not hypothesis.baseline:
            issues.append("缺少基线方案 -> 无法衡量改善")
        for k, v in hypothesis.success_conditions.items():
            if isinstance(v, str) and v not in ["True", "False"]:
                issues.append(f"条件 '{k}' 的值 '{v}' 不可量化")
        return {"falsifiable": len(issues) == 0, "issues": issues}
```

### 结论等级

| 等级                  | 含义             | 后续动作                 |
| --------------------- | ---------------- | ------------------------ |
| Supported             | 实验证据支持假设 | 输出结论，进入独立复核   |
| Partially Supported   | 部分条件下成立   | 给出适用边界，继续实验   |
| Not Supported         | 假设被否定       | 输出否定证据和研究建议   |
| Insufficient Evidence | 数据不足以判断   | 设计区分性实验或补充实验 |

## 7. 边界情况应对（Edge Case Matrix）

### 已覆盖的边界

| 边界情况         | 对应模块                                    | 处理方式                        | 状态 |
| ---------------- | ------------------------------------------- | ------------------------------- | ---- |
| 任务包字段缺失   | research_lead.validate_task_package()       | 检测缺失字段 -> FAILED          | ✅   |
| 无假设可审       | review_agent 检测空列表                     | 回退 HYPOTHESIS_GENERATION      | ✅   |
| 计算预算耗尽     | state_machine.should_stop()                 | termination_reason = "预算耗尽" | ✅   |
| 连续无信息增益   | consecutive_no_gain_count                   | 达到阈值 -> CONCLUSION          | ✅   |
| 求解残差超标     | audit_agent.check_solver_credibility()      | 标记不可信 -> 不更新密度        | ✅   |

| 假设被明确否定   | verdict level = NOT_SUPPORTED               | 输出否定证据                    | ✅   |
| 最大迭代次数     | iteration_count vs max_iterations           | 强制终止                        | ✅   |
| 插件组合非法     | compatibility_matrix.is_known_combination() | 禁止执行，提示原因              | ✅   |

| 边界情况                     | 当前行为                   | 应该做的                                                   | 优先级 |
| ---------------------------- | -------------------------- | ---------------------------------------------------------- | ------ |

| 多条诊断规则同时触发         | 各自输出                   | 优先级裁决: 连通性 > 残差 > 灰度 > 柔度                    | P1     |
| 两个假设实验结果无法区分     | INSUFFICIENT_EVIDENCE 回退 | 设计区分性实验，在分歧最大的条件下测试                     | P1     |

## 8. 纠偏机制评估

### 8.1 数据/代码缺失应对

**现状**：

- 任务包校验仅检查 JSON key 存在性，不检查数值合理性和文件存在性
- 插件缺失时 validate_plugin_combination 返回 valid=False，但无自动回退方案

**建议增加：插件缺失回退链**

```python
FALLBACK_CHAIN = {
    "heaviside_projection": ["none"],                        # 无Heaviside则不投影
    "joint_feedback_controller": ["gray_feedback_controller",
                                   "periodic_controller"],   # 降级为单一反馈或固定调度
    "cuda_mex": ["cpu_top3dxl"],                             # GPU不可用降级CPU
    "mma": ["oc"],                                           # MMA不可用降级OC
}
```

### 8.2 模糊假设检测

**现状**：

- CandidateHypothesis 数据模型强制要求 success/failure_conditions、metrics、baseline，结构上约束了假设可证伪性
- 但实际 LLM 生成的内容未被质量检测

**建议**：在 REVIEW 阶段前增加 `HypothesisQualityChecker`，对以下问题打回：

- 缺乏量化 success/failure 条件
- 表述含 "might"、"possibly"、"可能" 等不可证伪词汇
- 缺少基线方案

### 8.3 纠偏路径完整性

| 纠偏场景                     | 当前路径                            | 建议路径                                            | 状态   |
| ---------------------------- | ----------------------------------- | --------------------------------------------------- | ------ |
| 假设被部分否定但方向仍有价值 | 回到 HYPOTHESIS_GENERATION 全盘重来 | 新增「假设精炼」状态，保留合理部分，调整参数/权重   | 🔴缺失 |
| GPU/CPU 偏差过大             | 无明确路径                          | 新增「求解器诊断」状态，修复后重做                  | 🔴缺失 |
| 两个假设无法区分             | INSUFFICIENT_EVIDENCE 回退          | 新增「区分性实验」状态，设计针对性对比              | 🔴缺失 |
| 参数导致结构断连             | 无参数回滚机制                      | RollbackManager 保存 checkpoint，回滚到最后稳定状态 | 🔴缺失 |
| 插件不可用                   | 返回 valid=False                    | 自动查询回退链，选择替代插件                        | 🔴缺失 |

## 9. 知识库推荐架构

### 当前架构（关键词匹配 + JSON 文件）

### 各层选型对比

| 层级        | 推荐技术               | 理由                                 | 替代方案                  |
| ----------- | ---------------------- | ------------------------------------ | ------------------------- |
| L1 文件系统 | 本地文件 / S3          | PDF/STL/MAT 二进制文件不适合放数据库 | MinIO（分布式）           |
| L2 结构化   | **SQLite**       | 零配置、内嵌、支持 JSON1 + FTS5      | DuckDB（分析查询更优）    |
| L3 语义     | **FAISS** (Meta) | 纯向量检索、CPU 可跑、余弦相似度     | ChromaDB（自带embedding） |

### 知识库自进化机制

```python
class KnowledgeBase:
    """可自进化的知识库"""

    def add_experiment_result(self, result, verdict):
        """每轮实验后将结果与裁决写入知识库"""
        # 1. 写入结构化层
        self.sqlite.insert("experiments", {
            "run_id": result.run_id,
            "hypothesis_id": result.hypothesis_id,
            "compliance": result.objective.get("compliance"),
            "gray_ratio": result.quality.get("gray_ratio"),
            "verdict": verdict.level.value,
            "confidence": verdict.confidence,
        })
        # 2. 更新向量索引
        embedding = self.embedder.encode(f"{verdict.evidence_summary} {verdict.diagnostics}")
        self.vector_index.add(embedding, metadata={"run_id": result.run_id, "type": "result"})

    def query_similar_experiments(self, current_issue, top_k=5):
        """给定当前问题，检索历史中最相似的实验"""
        query_vec = self.embedder.encode(current_issue)
        hits = self.vector_index.search(query_vec, top_k)
        return [self.sqlite.query_experiment(h.id) for h in hits]

    def detect_knowledge_conflict(self, method_a, method_b):
        """检测两篇论文对同一方法是否矛盾"""
        card_a = self.get_method_card(method_a)
        card_b = self.get_method_card(method_b)
        if card_a and card_b:
            conflict = self._compare_conditions(card_a, card_b)
            if conflict:
                return {"conflict": True, "detail": conflict}
        return {"conflict": False}

    def get_seed_knowledge(self):
        """返回种子方法卡片库（首次运行时植入）"""
        return self.sqlite.query("SELECT * FROM method_cards WHERE is_seed = 1")
```
